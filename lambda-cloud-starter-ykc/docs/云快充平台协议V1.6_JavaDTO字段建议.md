# 云快充平台协议 V1.6 - Java DTO 字段建议

## 目标

为实现编解码提供统一的 Java 字段命名与类型选择建议；各帧的字段明细以 [云快充平台协议V1.6_完整报文参数对照表.md](file:///Users/jin/developer/projects/lamuda-cloud-parent/lambda-cloud-starter-ykc/docs/云快充平台协议V1.6_完整报文参数对照表.md) 为准。

## 通用类型约定

| 协议数据类型 | Java 类型建议 | 备注 |
|-------------|--------------|------|
| BCD 码 | String | 以“数字字符串”表达（保留前导 0）更安全，避免 long 溢出与前导 0 丢失 |
| ASCII 码 | String | 若协议要求“反序上送”，在编码/解码层做转换，DTO 内建议仍保持正序语义 |
| BIN 码（无小数） | int/long | 协议约定小端；1/2 Byte 用 int；4/5 Byte 用 long |
| BIN 码（带倍率） | BigDecimal 或 long + scale | 例如电压/电流/电量/金额等；建议在 DTO 中直接暴露 BigDecimal（更贴近业务） |
| CP56Time2a（7 Byte） | java.time.LocalDateTime | 解码时注意“毫秒/分钟/小时/日/月/年”等位域 |
| Bit 位字段 | int/long | 保留原始位图；再提供业务枚举/布尔派生字段（可选） |

## 通用字段命名（高频复用）

| 中文字段 | Java 字段名 | 说明 |
|---------|------------|------|
| 桩编号/桩编码 | pileCode | BCD(7) |
| 枪号 | gunNo | 多数帧为 1 Byte（BCD 或 BIN），建议统一用 int |
| 交易流水号 | tradeNo | BCD(16) |
| 逻辑卡号 | logicCardNo | BCD(8) |
| 物理卡号 | physicalCardNo | 协议里常以 8 Byte（BIN）出现，建议 DTO 用 16 进制字符串表达（保持原样） |
| 账户余额/修改后账户金额 | balance | BigDecimal（2 位小数） |
| 鉴权成功标志 | authOk | boolean（0x01 true） |
| 失败原因 | failReason | int（枚举值） |

## DTO 示例（仅展示骨架）

```java
import java.math.BigDecimal;
import java.time.LocalDateTime;

public record FrameHeader(
        int seq,
        int encryptFlag,
        int frameType
) {}

public record PileLoginReq(
        String pileCode,
        int pileType,
        int gunCount,
        int protocolVersion,
        String softwareVersion,
        int networkType,
        String simIccid,
        int operator
) {}

public record TradeRecordUpload(
        String tradeNo,
        String pileCode,
        int gunNo,
        LocalDateTime startTime,
        LocalDateTime endTime,
        BigDecimal totalKwh,
        BigDecimal totalAmount,
        String vin,
        int tradeFlag,
        LocalDateTime tradeTime,
        int stopReason,
        String physicalCardNo
) {}
```
